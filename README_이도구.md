# 전결 길잡이

일반 결재·대결 여부와 소속 팀을 확인하고 규정 및 사례의 적용 조건과 출처를 안내하는 웹 도구입니다. 일반 이용 화면과 로그인 관리자 화면을 제공합니다.

## 실행

Python 3.12 이상에서 별도 패키지 설치 없이 실행합니다.

```sh
python3 server.py --init-admin
python3 server.py --host 127.0.0.1 --port 8080
```

관리자 아이디는 `admin`입니다. 최초 비밀번호는 `.local/admin-initial-password.txt`에서 운영자 본인이 확인하며, 첫 로그인에서 반드시 변경해야 합니다. 비밀번호는 출력·공유하지 않습니다. 변경 후 초기 비밀번호 파일은 제거됩니다. 초기화 명령은 기존 계정이나 사례를 덮어쓰지 않습니다.

일반 화면은 `/`, 관리 화면은 `/admin`입니다. 서버 방식으로 운영하면 관리자에게서 공개한 사례가 일반 화면을 새로고침할 때 반영됩니다. `index.html`만 여는 정적 버전은 파일에 담긴 사례 사본을 사용하며 관리자 저장소와 연결되지 않습니다.

두 ZIP의 차이, HTTPS와 영구 저장소 설정, 백업 방법은 [DEPLOY.md](DEPLOY.md)에 있습니다. 실제 인터넷 게시·도메인 연결은 수행하지 않았습니다.

## 일반 이용 화면

1. 일반 결재 또는 대결 선택
2. 소속 팀 입력: 안전경영팀·비서팀·홍보팀·감사팀은 사장직속, 그 외 팀은 본부 소속(사용자 지정 분류)
3. 질문과 필요한 조건 입력
4. 전결 기준, 적용 조건, 근거 문서·쪽수 확인

규정 38쪽 전체 텍스트와 전결권 표시 860개를 검색합니다. 일반적인 직위별 휴가·근태·국내외 출장과 계약 조건은 검증한 규칙으로 안내하며, 불명확한 대상·단계·금액은 추가 확인합니다. 그 외 업무는 관련 표·본문을 조회하고 원문을 함께 확인합니다. 자동 추출한 모든 표의 의미와 모든 자연어 질문을 검증했다는 뜻은 아닙니다. 외부 AI API는 사용하지 않습니다.

일반 규정과 `규정에 규정되어 있지 않은 사례`를 구분합니다. 원자료의 7개 사례에는 조건별 계산을 연결했습니다. 선금 사례는 후속 정정 답변인 8. 예산집행 계획수립 기준을 반영했습니다. 월 업무추진비 100만원 사례를 100만원 초과까지 무제한 확대하지 않습니다.

새로 등록한 사례는 검색어·대표 질문으로 찾고 적용 조직과 조건 일치 여부를 확인한 뒤 저장된 답변을 안내합니다. 기존 사례를 관리 화면에서 수정하면 입력한 조건과 답변을 사용하는 사례로 전환되므로 기존 금액·범위 조건을 빠짐없이 유지해야 합니다. 규정에서 직접 확인되는 기준은 새 사례로 덮어쓰지 않습니다. 확인 부서·확인일이 없으면 미기재로 표시합니다.

대결은 부재·업무 범위·기본품의 승인·위임 기록을 확인합니다. 기본품의 자체와 새로운 의사결정은 제외하고, 직급별 위임 방법 및 결재경로를 안내합니다. 실제 대결자를 추정하거나 내부망 연결·상신·자동 실행을 수행하지 않습니다. 감사 조직의 별도 규정과 실제 재위임 내역은 별도 확인 대상입니다.

## 사례 관리

- 로그인 및 초기 비밀번호 변경
- 사례의 제목·질문·검색어·적용 조직·조건·답변·근거·검토 기록 등록
- 임시 저장, 검토 후 공개, 수정, 공개 해제
- 공개 중인 사례의 수정안은 따로 저장하고 다시 공개할 때 교체
- 서버 재시작 후에도 SQLite에 계정과 사례, 변경 이력 유지

현재 관리자 등록은 일반 결재 사례에 적용합니다. 대결은 매뉴얼 기반 안내를 사용합니다. 사례 확인자 기록은 실제 이름 대신 확인한 부서·역할로 입력하며, 확인하지 않은 날짜를 자동 생성하지 않습니다.

## 데이터와 보안

- 규정: 사용자 확인을 받은 2026.04.22 개정 공개본. 이후 개정 여부는 별도 확인 필요
- 대결 매뉴얼: 사용자가 분석과 외부 공유를 허용한 7쪽 안내. 실제 이름·연락처·화면 예시 인명 제외. 3~5쪽 이미지는 절차를 재구성했으며 원본 PDF는 배포 파일에 포함하지 않음
- 사례: 공개·익명화된 첨부 7건을 구조화. 출처와 원문 줄 번호 보존, 실제 검토자·검토일은 추정하지 않음
- 질문은 브라우저 메모리에서 처리하며 외부 API로 보내거나 서버 로그에 남기지 않음
- 비밀번호는 PBKDF2 해시, 세션은 HttpOnly·SameSite 쿠키, 변경 요청은 CSRF·Origin 검사
- 로그인 시도 제한, 저장 충돌 확인, 본문 크기·필드 길이·쪽수 검증
- `/api/cases`와 `/data/cases.js`는 공개본만 제공. 초안은 인증된 관리자만 조회
- 운영 DB·초기 비밀번호·세션·소스·첨부 원본은 정적 허용 경로에서 제공하지 않음
- `.local/`과 인증 파일은 Git 및 배포 ZIP에서 제외. 운영은 HTTPS·Secure 쿠키와 영구 저장소 사용

공사 로고나 공식 서비스 표지는 사용하지 않았습니다. 인터넷에 실제로 공개할 때는 운영자가 적용 자료·접근 범위와 최종 규정 해석을 확인해야 합니다.

## 검증

```sh
node --test *.test.js
python3 -m unittest server_test.py -v
```

JavaScript 213개 및 실제 HTTP 통합 10개 통과. 기존 규정·계약·대결 회귀, 7개 사례의 금액 경계·조건 분기, 관리자 사례의 적용 조건·공개 상태·조직 범위, 규정 우선 적용을 검사했습니다.

이 환경에 이미 설치된 Chromium/Playwright로 아래 화면 검증도 수행했습니다.

```sh
node scripts/browser_smoke.js
node scripts/admin_browser_smoke.js
```

관리자 첫 로그인/비밀번호 변경, 초안 비공개, 공개 후 일반 질의응답 연동, 수정안과 공개본 분리, 서버 재시작 저장, 재공개·공개 해제, 로그아웃 권한, 모바일 및 키보드 동작을 확인했습니다. 이 테스트의 사례와 계정은 임시 저장소에만 생성하고 삭제합니다.

## 파일 생성

- `python3 scripts/build_single.py`: 일반 결재·대결·기본 사례를 포함한 단일 HTML 생성
- `python3 scripts/build_single.py --public-regulation-only`: 공개 규정만 포함한 별도 사본
- `python3 scripts/package_release.py`: 일반배포용·관리자통합용 ZIP 생성. 비밀번호·DB·세션 제외
- `python3 scripts/extract_regulation.py`: Poppler와 Python 표준 라이브러리로 규정 검색 자료 재생성

단일 HTML과 일반 정적 ZIP은 생성 시점의 사례 사본입니다. 홈페이지에서 계속 사례를 관리하려면 관리자 통합 서버를 운영해야 합니다.
